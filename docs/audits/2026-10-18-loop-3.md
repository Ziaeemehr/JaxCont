## Claims verified

- **0.5.0 API migrations:** removed solver/problem/configuration classes are absent from the public exports; functional replacements exist. Installation dependency floors match `pyproject.toml`, including Equinox. Minimal fold/Hopf defaults and widths, extended decoders, `PeriodicArgs.user_args`, static curve layouts, dtype-derived tolerances, positive mesh/span checks and the new low-level `step_update`/`args` positions match source. Migration examples were inspected, not executed.
- **Numerical and differentiation changes:** source and inspected assertions support the `1/n_state` default metric, accepted-point versus attempt budgets, validated/rejected event split, tracked-mode seeds, rightmost dominant eigenvalue, centered PD-switch amplitude and doubled Hopf coefficient (`l1=-2`, unchanged default classification tolerance). Representative assertions are in `test_functional_api.py`, `test_branch_switch.py`, `test_hopf_normal_form.py`, `test_pd_switch.py` and `test_loop1_audit_gaps.py`. The while/scan distinction and fixture-scoped transformation matrix agree with the engine dispatch and cited regression tests; eager candidate refinement and eager-only bothside/PD switching remain explicit limits.

The pair return and strategy argument, flow-alignment identity, failed-spectrum masking/raising, log-magnitude stability and repeated-mode derivative limitations match `stability/floquet.py` and the Schur implementation/tests. The rotating scaled-factor assertion in `test_periodic_schur.py` supports preservation of a small multiplier in its tested fixture; this is numerical accuracy evidence, not a timing claim. The ProductFloquet status wording exception is L3-F4.
- **Evidence inventory:** exactly **23 cases: 8 PASS, 1 FAIL, 7 PENDING, 7 UNSUPPORTED**, matching the overview.
